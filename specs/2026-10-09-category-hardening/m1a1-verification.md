## What was already shipped

Stage 1 M8 commit [`e0143af`](https://github.com/agentpm-dev/cli/commit/e0143afc0dd92dbe1c05d3fe27bb19c8325ed02f) adds exactly `"standard": {}` to the root properties in the existing manifest schema. Comparing its parent and committed schema confirms that this was the only structural change: root `additionalProperties: false` and every `$defs` entry are identical. The field is still permissive in the [current schema](../../schemas/agentpm.manifest.schema.json#L1714).

The [existing Stage 1 publication record](../2026-10-06-immediate-hardening/tasks.md#L626) and [Stage 2 handoff](spec.md#old-client-forward-compatibility--tolerance-release-before-any-standard-emission) identify **CLI 0.1.36**, publication/installation confirmed **2026-10-22**, as the concrete minimum for future outdated-client guidance. No replacement version is invented here.

This milestone closes verification gaps around that existing support. No schema, dependency, lock format, runtime behavior, public documentation, version or production state changes. `agentpm-api/docs` needs no workflow update because the shipped user behavior is unchanged. The source tests remain in the ordinary workspace suite; no new validator, fixture engine or CI workflow is added.

## Historical-client evidence and limits

A Python subprocess probe read the actual schema snapshots with `git show e0143af^:schemas/agentpm.manifest.schema.json`, `git show e0143af:schemas/agentpm.manifest.schema.json`, and `git show v0.1.33:schemas/agentpm.manifest.schema.json`.

It removed `standard` from a copy of the tolerance commit's schema and asserted exact JSON equality with the parent, including unchanged `$defs` and root closure. It then wrote the v0.1.33 schema and a minimal legacy Agent into a temporary directory and invoked the current `target/debug/agentpm lint --schema <schema-file> --format json <manifest-file>`:

| Schema / manifest                                    | Observed result                                                |
| ---------------------------------------------------- | -------------------------------------------------------------- |
| v0.1.33 schema, legacy manifest without `standard`   | Exit **0**                                                     |
| v0.1.33 schema, same manifest with opaque `standard` | Exit **1**; error at `/additionalProperties` naming `standard` |
| Current schema, same standard-bearing manifest       | Exit **0**                                                     |

This replays the historical structural failure with today's validator; it does **not** claim execution of a historical 0.1.33 or 0.1.36 binary. The original old-client failure and 0.1.36 publication remain independently recorded in the stage handoff. Pre-tolerance installed clients still need an upgrade before schema-validating standard-bearing manifests; this work does not patch binaries already distributed.
