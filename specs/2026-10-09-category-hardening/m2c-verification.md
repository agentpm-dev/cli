## Implementation boundary

The Registry now has its own offline Python engine in `app/apds/`: pinned contract loading, Draft 2020-12 schema diagnostics, standalone semantic relationships, exact selected composition checks and packaged-content inspection. It reads real supplied declarations and evidence. It never invokes Rust, reads expected fixture answers, trusts a client verdict, executes a Runner, or fetches an arbitrary schema.

The test adapter and parity/source checker are in `scripts/apds_corpus.py` and `scripts/check_apds.py`, outside both the runtime engine and versioned contract. The adapter asserts expected findings against actual Python diagnostics before projecting them into the portable corpus format. The Rust export is likewise generated by actual CLI integration tests, not copied from expectations. The portable projection intentionally targets each case's normative findings; full native diagnostics remain available separately.

The Python module entrypoint supports local inspection and makes representative independent review repeatable. Its requested scopes are `standalone`, `resolved` and `packaged`; only a conformant requested scope exits 0. Graphs carry exact owner/field/selected-artifact edges, not name-based guesses. Unavailable evidence is incomplete; supplied complete missing/invalid content is a violation; known violations take precedence over unsupported/incomplete checks. Missing standard declarations are strict authored defects here, not fabricated historical inference.

Existing publish/install routes, ACLs, scanning, signatures, DTOs, startup, migrations, SDKs and Runner behavior are unchanged. The engine is not an enforcement hook; M4 retains Registry publication integration. Ordinary CLI authoring/preflight remains M3B. No user-facing validation claim is added to published Registry data by this work.

`jsonschema==4.23.0` moves from test-only to explicitly pinned runtime use. Direct `referencing==0.37.0` and the already-resolved `packaging==25.0` are declared explicitly; the existing `dep-logic` dependency supplies independent Python requirement/marker algebra. `requirements.txt` was regenerated through `uv pip compile`; existing dependency versions are unchanged.

## Local discrepancy log

No cross-language semantic mismatch remains open in the tested corpus or additional native edge set. Python implementation defects found during construction were corrected without changing normative answers:

- An early local check read a nonexistent Memory model field; fixed to the actual `model` declaration, restoring document/sequence retrieval and append-only checks.
- Blank Loop objective checks were initially missing; added with the same explicit Unicode whitespace boundary rather than Python's broader `str.strip` class.
- Malformed kind values initially reached semantic set lookups; structurally unusable inputs now stop at concrete schema diagnostics instead of crashing or being coerced.
- Union diagnostic selection initially chose a different Memory operation branch through `$ref`; it now follows the declared discriminator and reports the actual `inputs` constraint for transform arity.
- Additional requirement tests require the same existing distribution-only, satisfiable-constraint and marker-overlap semantics as Rust, using Python libraries independently. No installation or resolver is run.

Capability limits are deliberate and disclosed: unknown Knowledge vector/index representations and composed/ref-mediated non-persistability projection compatibility return `unsupported` with unevaluated rules. Neither engine claims arbitrary record-schema satisfiability from a shallow scan.

## Independent review exercise and diagnostic metadata

User supplied Claude’s independent exercise report on **2026-11-15**. Claude invoked both native entrypoints directly and compared their outputs, rather than relying on the exported parity rows. The nine selected cases cover every status/scope combination present in the indexed corpus:

- `valid-agent`, `selector-unsupported`, `invalid-agent-required`
- `composition-complete`, `phase-unknown`, `graph-unavailable`
- `knowledge-context-files`, `knowledge-context-missing`, `knowledge-content-unavailable`

All nine agree on the compared conformance fields and index expectations. Eight agree on the reported coverage metadata as well. For `invalid-agent-required`, Rust lists eight `evaluated_rules`; Python lists four. Both report `nonconformant` with identical `unevaluated`. Rust completes optional binding/dependency absence checks despite the missing description; Python stops local relationship checks after the structural error. Claude classified this as nonblocking and outside the normative parity contract.

**Decision:** `evaluated_rules` means IDs associated with checks the implementation completed in the requested scope, including checks that pass because an optional declaration is absent. It does not mean that a test exercised every branch, that every clause of the rule was evaluated, or that Runner behavior was established. The same rule can have other checks left unevaluated. Merely being listed in the standard is insufficient; implementations may complete different checks before stopping on an error.

The CLI lint documentation, both implementation guides and the durable parity report now state this boundary. The comparison includes `case_id`, `level`, `status`, targeted rule/document/path/severity `findings`, and `unevaluated`; it deliberately excludes native `evaluated_rules`, notes, messages and schema paths. No validator code, parity projection, canonical standard, snapshot or expected result was changed to force matching bookkeeping. This closes the reported documentation decision without claiming byte-identical native reports.

Clarification verification: from the Registry root, `REGISTRY_PRIVATE_KEY_B64=AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA= .venv/bin/python -B -m pytest -q tests/test_docs_content.py` passed **5 tests and 150 subtests**, and `.venv/bin/python -B scripts/check_apds.py` passed all **129** Python corpus cases with the unchanged pinned inventory. Touched Markdown/MDX/JSON passed Prettier; `git diff --check` passed in both repositories.
