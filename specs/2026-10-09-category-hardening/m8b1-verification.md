# M8B.1 — Global shell verification

Scope: M8B.1 only. Zack approved the [D21 adoption sheet](m8b1-d21-adoption.md) on 2026-11-26 before implementation, then explicitly corrected D21-07 to retain the 56px masked grid at .085 and sky .13 / fuchsia .10 washes. That correction is incorporated in the sheet and implementation.

Implementation is ready for independent review. Hosted CI, production deployment and a real signed-in operator session are not claimed by this local record.

## Changes and boundaries

- One server Header still owns Clerk lookup; one HeaderFrame supplies responsive navigation for both account states. Sign up uses the existing `/signIn?mode=signup` flow. The authenticated profile link remains functional and named. D21-03 explicitly excludes a new notification service/menu.
- One GlobalSearchClient implementation supplies responsive desktop/mobile instances with shared query/kind state and only one visible field. The widened selector sits inside the search bar; kind-specific placeholders match the dropdown labels with consistent capitalization, using Agent Packages for the `agents` option. Explore retains only its dedicated page search/sort; keyboard shortcuts target that field. Its pending provider stays local to Explore. Docs retain separate content navigation/search.
- Mobile restores the original always-visible branding/navigation/account row and a dedicated search row below a slate-700 divider. Branding is white at rest and hover, with its original 32px mark/16px type; links retain 14px type and 12px spacing. Only the link area scrolls at exceptionally narrow widths. Desktop search has more space on both sides; no primary-header Explore link.
- Shared SectionHeader/Section compose existing Panel surfaces only for technical groups; open sections remain unboxed. RailLayout reuses Explore's 3/9 geometry. DetailHeaderLayout, ContentGrid and PageIntro are available for later page migrations. Optional facts reuse AtAGlance's availability rule: unknown values disappear and meaningful zero survives.
- One Footer has compact/full variants, real destinations and dynamic year. Full is the root default. Its stacked narrow brand/legal content is centered above horizontal Product/Develop/Project groups, with one SDKs link. It sits outside main so the global contentinfo landmark is exposed correctly.
- Kind assignments are centralized in `src/lib/package-kinds.ts`; eight existing cards, M8B primitives and header/facet kind references consume them. Full and compact labels preserve their existing contexts. Badge styles and ToolBox-generated identities are unchanged.
- One HeroBand component spans the viewport while preserving content width. Landing uses the approved .13/.10 washes and .085 grid; detail headers across all eight kinds use the softer approved .10/.09 washes and .075 grid. Measurement includes page padding/breadcrumbs above the identity header, avoiding a plain top strip. Explanatory prose has a 14px implementation floor; compact labels and existing code exemptions remain; shared command blocks adopt the approved terminal chrome, 14px code, format buttons and copy icon, preserving exact copied bytes. New shell controls have visible focus and reduced-motion handling.
- The APDS reference is the first content-route adoption: prose is open at the existing max-w-3xl reading measure, the chapter/rule index remains a technical Panel, and headings clear the measured global header height. Frozen content is unchanged.

No Agent/Tool page rearrangement, Explore result-row redesign, homepage content rewrite, Health-tab decision, feature data, schema, Registry runtime, CLI or SDK contract change is included.

```sh
node scripts/check-shell-browser.mjs /private/tmp/agentpm-shell-check http://localhost:3000
# Optionally append a local package-detail URL to also check its band.
```

This optional check uses installed Chrome, an isolated profile and no browser dependency. It refuses a non-loopback target. SSR layout fixture output is generated by `AGENTPM_SHELL_CAPTURE_DIR` when running `src/components/Shell.test.tsx`; no fixture route ships in the app.

## Review corrections (2026-11-26)

The standards anchor offset now has a responsive CSS default before hydration: 117px below the existing 1024px header breakpoint, 67px at and above it. HeaderFrame continues to replace that default with its measured height. The incorrect 7rem fallback was removed. Browser assertions cover native hard-load hash positioning with hydration bundles blocked, a normal hydrated hard load, and an actual in-page rule-link click at 1440/1024/1023/768/390/320. Streamed Suspense placeholders can temporarily be shorter than the final header; the pre-hydration assertion checks clearance against the responsive default, and the hydrated assertions check the actual header bottom plus 16px. Combined package identity/tab offsets remain M9A.

Header search again permits empty/whitespace submission to browse the selected category. It starts a fresh Explore URL with default sort, without stale facets or cursor, and emits no text-search event for that browse action. Nonempty submissions explicitly report Relevance and one type parameter (including all): the shared analytics vocabulary counts type as a filter, so the previous computed count was one, not zero. Tests cover both header variants, selected-category browsing, stale URL state and exactly one allowlisted event without query/cursor leakage.
