## Changes and boundaries

- Plain `agentpm init` now creates `my-agent`, with a useful nonblank purpose, the supported standard and version-pinned editor schema. Explicit Agent initialization produces identical files. Optional dependency arrays are empty and no Loop is imposed. Immediate output explains lint, Components, and the Loop/model prerequisites for Harness execution.
- All eight kinds, both Knowledge modes and `export --manifest` emit `standard: {"id":"agentpm","version":"1.0.0"}`. The pinned `$schema` URLs already introduced in M1B are retained and asserted, not fetched or treated as selectors. Export shortens a long Tool leaf before appending `-skill`, keeping the generated local name within the existing 64-character limit without changing the dependency reference or output directory.
- JSON templates are parsed, authored values inserted as strings, validated by the existing standalone engine and serialized. User text is not interpolated into JSON or recursively interpreted as another template token. Identity fields stay near the top of the generated manifest without changing global JSON map ordering or historical signing bytes. Skill frontmatter descriptions use quoted JSON/YAML scalars too.
- Init checks names/descriptions and all generated destinations before writing. Existing generated files, staging paths, non-directory parents and generated-subdirectory symlinks are rejected. An existing Tool `main.py` remains intentionally preserved. This retains per-file atomic writes; it is not a directory transaction or a guarantee against concurrent writers, disk exhaustion or interruption between files.
- Tool source/runtime/entrypoint defaults, explicit Python/Node authoring, Knowledge/Memory builds, Template `new`, existing `export --force` and public run/publish/install contracts remain covered by regression tests. No automatic standard insertion was added to existing manifest-rewriting paths.
- Tool scaffolding remains **Python only**, as it was before M3A. The plan's "Python/Node" wording does not establish an existing Node template: Node coverage is manually authored manifests and payload packaging, including `tests/payload_compatibility.rs::other_tool_runtimes_keep_their_existing_packaging_behavior` in the full workspace baseline, not Node scaffold generation or the init snapshot suite. The preservation checklist now makes that distinction explicit. No Node init option or template is claimed or added.
- README, command help, init/export/lint docs and the Quickstart explain the changed default and generated declaration. The existing manual scaffold helper now expects the supported declaration. No public package content or version was republished.
