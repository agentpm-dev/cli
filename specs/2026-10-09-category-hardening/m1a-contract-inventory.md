Three labels separate observations that must not be silently promoted into the future standard:

- **S — structural contract:** the current schema's shapes, types, required fields, enums and closure rules. These are existing constraints, not an assertion that every one will survive the APDS freeze unchanged.
- **P — candidate portable semantics:** authored meaning that should be preserved across consumers, such as dependency kind, binding scope, implicit Loop outcomes and Memory operation references. Final normative rules belong to M1C and need independent review.
- **I — AgentPM implementation policy:** Registry authorization, filesystem layout, CLI commands, prompts, scheduler timing, provider support, trust/scan policy and local readiness. These do not become APDS requirements merely because AgentPM implements them.

An observation can have both a structural and a semantic part. A source discrepancy remains a reconciliation item, not a new standard rule.

| Diagnostics        | stderr is separate from the returned JSON value; diagnostic text alone is not a failed exit. An unparsable stdout response produces `ERR_TOOL_OUTPUT_NOT_JSON` (`tool stdout was not valid JSON`, declared at `runner.rs:46`); an unsuccessful child produces `ERR_TOOL_EXITED_UNSUCCESSFULLY`. Rejecting invalid responses and failed subprocesses is candidate portable behavior; the exact AgentPM error strings, machine categories, log paths, byte budgets and timeout/cleanup mechanisms are **I**. Conversely, a schema-valid domain result such as `{ "ok": false, "error": "..." }` from a zero-exit Tool remains returned data, not automatically an invocation failure. M1C/M2A should preserve the process contract and distinguish transport/subprocess failure from application-level result data in semantic rules and fixtures.

M17 makes this path the execution authority for both SDKs. Their versioned stdin SDK-request wrapper and the CLI's `--machine` result envelope are **host transport**, not the bytes a Tool must receive or emit: the child still receives the unwrapped input JSON and returns its own JSON result. Current SDK compatibility mode additionally extracts a valid JSON object from noisy historical stdout when strict whole-stdout parsing fails ([`runner.rs:559`](../../crates/agentpm-cli/src/runner.rs#L559)). This legacy adapter is **I**, not a second portable Tool-output protocol or permission for new Tools to log on stdout. Existing tests explicitly preserve strict normal-run parsing and schema-valid domain-failure results (`runner.rs:1338`, `runner.rs:1680`).

## Tool environment resolution

| Execution behavior   | Observed meaning                                                                                                                                                                                                                                                                                                     | Evidence / class                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Environment layering | Start with ambient process environment; fill only absent keys from `environment.vars` defaults; overlay `entrypoint.env`; finally overlay caller invocation overrides. For ordinary Tool variables, caller wins over entrypoint, entrypoint wins over ambient/defaults, and defaults never replace an existing value | [`runner.rs:761`](../../crates/agentpm-cli/src/runner.rs#L761). **P — candidate portable semantics** |
| Required variables   | Check the resulting environment for required declared keys after merging and managed-runtime isolation. Presence is the current check: an existing empty value is not missing and does not cause a default to be substituted                                                                                         | [`runner.rs:802`](../../crates/agentpm-cli/src/runner.rs#L802). P; isolation details below are I     |

For example, a variable with default `fallback`, ambient value `ambient`, entrypoint value `entrypoint` and caller value `caller` resolves to `caller`. Removing the caller override yields `entrypoint`; removing that overlay yields `ambient`; only an absent ambient key allows `fallback`. This precedence affects the meaning of the same authored package across consumers, so M1C/M2A should preserve it in semantic rules and fixture expectations rather than leave it as an implicit Runner choice.

The Stage 1 [M17 audit](../2026-10-06-immediate-hardening/m17-audit.md#L24) already treats caller/default precedence as contractual, and the [Node SDK docs](../../../agentpm-api/docs/v0.1/sdks/node.mdx#L487) and [Python SDK docs](../../../agentpm-api/docs/v0.1/sdks/python.mdx#L474) describe the same layering. Both SDK Tool callables delegate to this CLI execution path.

Keep the scope of the rule explicit: dependency-bearing managed Python applies runtime isolation **after** the merge ([`runner.rs:780`](../../crates/agentpm-cli/src/runner.rs#L780)). It sets `VIRTUAL_ENV`, prepends the managed interpreter directory to `PATH`, and removes `PYTHONHOME`/`PYTHONPATH` case-insensitively. Those reserved-variable/runtime mechanics are **I**, separately inventoried; caller precedence does not promise permission to override them. Legacy Python retains its declared `PYTHONPATH`. No runtime behavior changes in this audit.

## Bindings, phase lookup and Skill inheritance

The Agent's `bindings` object contains optional `global`, `phases`, `mcp` and `consumer_context`. Each global/phase scope may select `tools`, `skills`, `knowledge`, `profiles` and structured `memory`. Present arrays are nonempty and unique. A Memory binding requires `package` and at least one of `spaces` or `operations`; identifiers use the Memory snake_case vocabulary. MCP entries have stable IDs and selected Tool identities. Consumer context declares a safe relative file and optional token budget.

The composition trace is:

1. **Standalone lint:** [`manifest.rs:1829`](../../crates/agentpm-cli/src/manifest.rs#L1829) requires a Loop dependency when phase bindings exist, validates bound package identities against top-level declarations, and rejects duplicate selectors. It cannot check phase names or Memory selectors against unresolved Components.
2. **Resolved Harness plan:** [`harness_plan.rs:908`](../../crates/agentpm-cli/src/harness_plan.rs#L908) loads the selected installed Loop and checks its graph. [`harness_plan.rs:1116`](../../crates/agentpm-cli/src/harness_plan.rs#L1116) diagnoses unknown phase names. [`harness_plan.rs:1137`](../../crates/agentpm-cli/src/harness_plan.rs#L1137) collects global candidates and candidates from matching phase names; unknown phase scopes are skipped. [`harness_plan.rs:1596`](../../crates/agentpm-cli/src/harness_plan.rs#L1596) checks named Memory spaces/operations against the resolved Blueprint.
3. **Skill inheritance:** [`harness_plan.rs:1738`](../../crates/agentpm-cli/src/harness_plan.rs#L1738) reads each bound Skill's Tool declarations, obtains the installed Tool candidate and attaches the Skill's scope and provenance. A direct/inherited duplicate is diagnosed and deduplicated. Missing inherited Tools are suppressed. `skill.scripts` is not a command-execution grant.
4. **Effective phase:** [`effective_phase.rs:24`](../../crates/agentpm-cli/src/harness_engine/effective_phase.rs#L24) selects candidates from `global` or the exact `phase:<id>` scope ([line 379](../../crates/agentpm-cli/src/harness_engine/effective_phase.rs#L379)), deduplicates by identity, applies Loop denials and readiness, and builds the actual capability catalog. Tools, imported MCP Tools, Knowledge, direct Memory reads/writes and procedural Skill resources remain distinguishable.
5. **Runner exposure:** descriptors and action validation use the effective phase, not every installed dependency. CLI [`commands/harness.rs:1039`](../../crates/agentpm-cli/src/commands/harness.rs#L1039) initializes a machine session; SDK machine clients delegate execution to that process. SDK `loadAgent`/`loadSkill` return metadata and resolved references; they do not independently enforce phase capability policy.

Additive scope and inherited Tools are **P**. Candidate states (`available`, `pending`, `suppressed`, etc.), readiness probes, installed layout, warning severity, model prompts and ordering/deduplication implementation are **I**. Profile capability `requires`/`recommends` are expectations, not grants; current checks live at [`harness_plan.rs:1283`](../../crates/agentpm-cli/src/harness_plan.rs#L1283) and [line 1347](../../crates/agentpm-cli/src/harness_plan.rs#L1347). Bound Profiles combine global/phase candidates ([`effective_phase.rs:595`](../../crates/agentpm-cli/src/harness_engine/effective_phase.rs#L595)); constraint strength remains `required` or `preferred`. Do not standardize prompt order or infer deterministic natural-language conflict resolution.

## Loop interpretation and restrictions

- **S / P:** stable phase/outcome/checkpoint IDs, entry phase, exactly shaped transitions `from`/`on`/`to`; terminal targets exactly `$end`, `$abort`, `$handoff`. `archetype` is optional descriptive text, not a runtime switch.
- **P:** omitted outcomes mean exactly `complete`. CLI semantic lint inserts that implicit set and checks one transition per declared/implicit outcome, known targets, entry phase, duplicate identifiers and terminal reachability ([`manifest.rs:1520`](../../crates/agentpm-cli/src/manifest.rs#L1520)). Explicit empty outcomes fail schema validation.
- **S / P:** `access.tools`, `access.knowledge`, `access.memory.read|write` restrict phase capabilities; an omitted flag is not an explicit denial. An Agent binding does not override a denial. Approval checkpoints reference phases and rejection targets; Tool failure policy supports retry/fail_phase/abort/handoff with retry-specific fields; phase failure policy supports abort/handoff. Optional positive `limits.max_steps` is not `max_turns`.
- **I:** Harness requires a selected installed Loop to run an Agent ([`harness_plan.rs:771`](../../crates/agentpm-cli/src/harness_plan.rs#L771)); this is not a structural requirement on every Agent. It separately has provider/model needs, run limits, hooks, cancellation, repair and approval policy.
- **Discrepancy:** Harness's graph preflight ([`harness_plan.rs:999`](../../crates/agentpm-cli/src/harness_plan.rs#L999)) does not perform exactly the same checks as authored semantic lint: empty typed outcomes skip its transition-outcome membership check, and `$`-prefixed targets are treated differently from the schema's exact terminal enum. Typed installed readers are not proof that malformed stored content passed the authoring validator. Do not freeze those omissions as portable behavior.

Phase 6/7 comparison sources: [Profile contract](../2026-08-01-instruction-profiles/spec.md#manifest-contract) and [Loop/Agent bindings contract](../2026-08-09-loops-agent-bindings/spec.md). In particular, the latter's Memory binding rules distinguish operation participation from unrestricted access, and leave trigger evaluation to the runtime. These historical specs provide intended meaning; current source and tests provide implementation evidence.

## Template and Harness configuration boundary

Template surfaces are exactly `python-sdk`, `node-sdk`, `agentpm-run`, `agentpm-harness`, `agentpm-serve-mcp`, `multi-agent-workspace`. `stack` vocabulary is `python`, `node`, `shell`, `mcp`, `workspace`. Variables are generation-time values, not a mechanism for packaging runtime secrets. `entrypoints` describe generated-project usage; `new` scaffolds rather than automatically running those commands. Registry tar validation checks that a Template contains its declared scaffold root ([`tar_validation.py:47`](../../../agentpm-api/app/tools/domain/tools/tar_validation.py#L47)); CLI generation and blocking generated-manifest validation live in [`commands/new.rs:59`](../../crates/agentpm-cli/src/commands/new.rs#L59).

[`schemas/agentpm.harness.schema.json`](../../schemas/agentpm.harness.schema.json) is a **separate host configuration** with its own `$id` (`https://raw.githubusercontent.com/agentpm-dev/cli/refs/heads/main/schemas/agentpm.harness.schema.json`), Draft 2020-12, closed root and required integer `version: 1`. Its **36 `$defs`** are indexed with the manifest definitions. Root fields are `$schema`, `version`, `model`, `providers`, `scopes`, `runtime`, `hooks`, `knowledge`, `memory`, `mcp`, `approvals`, `trace`, `ui`. It supplies process/host implementations, provider/model choices, state/limits, trusted scope values, runtime mappings, embedding identities, MCP import/export scope, approvals and UI settings. These are **I**, not hidden Agent Package dependencies or APDS requirements.

[`harness_config.rs:497`](../../crates/agentpm-cli/src/harness_config.rs#L497) resolves host configuration; [line 568](../../crates/agentpm-cli/src/harness_config.rs#L568) validates embedded config schema; [line 595](../../crates/agentpm-cli/src/harness_config.rs#L595) adds semantic/runtime checks. Config and CLI overrides are not manifest rewrites. No provider/model is implied by APDS validity.

Machine transport is also an existing client contract: `protocol: "agentpm-harness-machine"`, `version: 1`, frame kinds `request`/`response`/`event`/`error`, with optional `id`, `method`, `payload`, `error`. See CLI `commands/harness.rs:1313` and Node SDK `src/harness.ts:30`. Initialize returns session protocol/version, preflight, MCP exports and required host services; registrations are then flushed before normal execution. This host protocol is **I**, separate from the manifest and from service-provider initialization protocols.
