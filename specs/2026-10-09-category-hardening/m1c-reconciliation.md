Date: **2026-11-14**. Baseline: CLI `0b1b9fe4781aed55fb0fb60d35411c8d5589b674`. Scope: **M1C only**. The public contract is [semantics.md](../../standards/agentpm/1.0.0/semantics.md); this internal record is implementation evidence, not another normative authority.

## Prerequisites and inclusion test

M1A/M1A.1/M1B are reviewed and complete. M1B's [merge evidence](m1b-verification.md#freeze-prerequisite-evidence) records Stage 1 M2/M11A ancestry and the public merged schema, plus confirmation that Stage 1 M12 classification is outside `agent.json`. M1C retains those exact schema bytes. The existing optional Python distributions and Template `agentpm-harness` execution surface remain valid.

Every candidate rule was considered against three grounds: **V** = artifact validity, **M** = portable authored meaning, **I** = intended interoperability. At least one is needed for a normative rule. The earlier R06 recommendation missed Phase 7B’s explicit authority rule. Its initial approval is **superseded** by the user’s review-time instruction to reverse that decision and preserve the prior contract. No runtime enforcement gap is asserted for keeping lifecycle authority separate. User confirmed the independent contract/readability review, including the revised Memory rules and subsequent trigger coverage, passed with no remaining findings on 2026-11-14. M2A’s initial fixture review still gates freezing/publication.

**Trigger reconciliation after spec-author review:** Phase 7B `Trigger semantics` defines count/capacity edges and rearming below the boundary, plus interval dormancy, initial state-dependent baseline and completion-time reset. These change observable eligibility, so MEM-008 now preserves them. Repeated evaluation/phase entry does not create another edge or restart an interval. Initial armed observation may qualify; successful execution consumes the edge, while failure retries remain a separate Runner policy. Phase-start/write yield points, the 30-second Harness cooldown, concrete operation-state rows and polling/storage architecture stay non-normative. Existing edge/rearm, interval dormancy/reset/restart and cooldown tests provide source evidence, not an obligation to copy the scheduler.

**Tool output compatibility after review:** TOOL-001 now explicitly separates strict APDS-conforming process output from identified legacy adapters. AgentPM’s `sdk_compatibility` extraction remains a compatibility mechanism, not permission for new conforming Tools to log on stdout or proof of strict output compliance. A Tool execution subheading makes the independent Tool contracts visible under chapter 5.

**Stateful case coverage after review:** the original A–P map did not directly exercise the strongest MEM-008 guarantees. Added Q–T for initial armed eligibility, unchanged-count no-refire, below-threshold rearming, and interval dormancy/baseline/reset. Two direct Harness regressions now exercise initial and repeated observations for both record-count and capacity triggers through the existing post-write lifecycle path. No runtime logic or normative rule meaning changed in this coverage correction.

## Decisions

- **D01:** one normative, human-readable `semantics.md`, eleven blueprint chapters, 56 stable rule anchors, a compact subject/scope index and a separate readable A–T interpretation map (A–P composition plus Q–T stateful triggers). Alternatives were a repeated long template per rule or an executable rule language; neither improves this bounded deliverable. The indexes locate rules; they do not execute a second semantic engine.
- **D02:** retain M1B's canonical directory, schema `$id`, byte-identical generated old path, LF attributes and whole-bundle checksums. Extend the existing CI check to semantic document integrity/example checks. Schema bytes are unchanged. The `apds-v1.0.0` tag is still an operator publication gate after reviewed semantics/corpus completion.
- **D19:** separate explicit declarations, completed validation scope, unsupported standards/capabilities, definite violations, unknown context, trust and Runner readiness. Public scopes/outcomes are logical meanings, not a new AgentPM API/DTO or mandatory diagnostic serialization.
