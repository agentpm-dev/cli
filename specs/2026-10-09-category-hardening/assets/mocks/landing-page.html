Agent Package Management

Agents are software. Treat them like it.

An Agent Package is a dependency declaration and a lifecycle, not a folder of prompts.

agent.json @zack/devwork-copilot 
{
  "standard": { "id": "agentpm", "version": "1.0.0" },
  "kind": "agent",
  "version": "0.1.10",

  "tools":     [{ "name": "@zack/summarize-text",          "version": "0.1.10" }],
  "skills":    [{ "name": "@zack/issue-triage-playbook",   "version": "0.1.1"  }],
  "knowledge": [{ "name": "@zack/devwork-maintainer-guide", "version": "0.1.0"  }],
  "memory":    [{ "name": "@zack/devwork-maintainer-state", "version": "0.1.0"  }],
  "profiles":  [{ "name": "@zack/devwork-maintainer-style", "version": "0.1.0"  }],
  "loop":      "@zack/devwork-triage-loop@0.1.0"
}

How the pieces fit together

Two run on your machine. Two are shared by everyone using AgentPM.

On your machine
Manager
agentpm

The CLI. Resolves dependencies, verifies releases, writes agent.lock and provisions runtimes.

Harness
agentpm harness

The built-in Runner. One way to run an Agent Package, and other Runners may support the standard independently.

Shared by everyone
Registry
agentpm publish

Where packages are published, versioned and signed, with integrity evidence attached to every release.

APDS
agentpm / 1.0.0

The open definition standard every package conforms to. Frozen, with a public schema and conformance corpus.
