# Release Band 1: production smoke checks using maintained examples

Run these commands locally, one block at a time. The publication commands create
real immutable versions in the production `zack` namespace. No provider/model
calls are needed. Retain their output and normal published URLs; never share a
token, passphrase or private signing key.

This first pass covers historical installs, compliant successors through both
protocols and fresh verified installs. Exact finalize retries and raw-client
rejection remain separate API checks; ordinary `agentpm publish` does not expose
the original finalize request. Do not count this first pass as all of step 9.

## 2. Install the historical releases in separate clean consumers

```bash
mkdir "$BAND1_SMOKE/historical-tool"
cd "$BAND1_SMOKE/historical-tool"
agentpm --base-url https://api.agentpackagemanager.com install \
  @zack/summarize-text@0.1.10 --require-signature --require-attestation --machine \
  2>&1 | tee "$BAND1_SMOKE/historical-tool-install.log"

mkdir "$BAND1_SMOKE/historical-agent"
cd "$BAND1_SMOKE/historical-agent"
agentpm --base-url https://api.agentpackagemanager.com install \
  @zack/devwork-copilot@0.1.8 --require-signature --require-attestation --machine \
  2>&1 | tee "$BAND1_SMOKE/historical-agent-install.log"
```

Expected: both commands print `{"schema_version":1,"status":"success"}`, including
installation of the Agent's historical dependencies. `--machine` retains a result
when piped to `tee`; ordinary non-TTY install output is intentionally quiet. These are install/cryptographic checks, with no Agent or Tool
execution. Keep both generated `agent.lock` files. Compare selected integrity
references with the retained production audit; install success alone does not
complete that historical-reference comparison.

do not require four platform-specific source artifacts.

## 4. Publish the compliant Agent Package

The first attempt exposed a CLI 0.1.45 defect: Agent packaging omitted the
explicitly declared README, and the Registry correctly rejected it with
`APDS-ID-004 /readme`. The same omission affects Templates and non-Python Tools
when their file selection does not already include declared display files.
CLI **0.1.46** is prepared with this correction; hold this step until review,
required CI and the patch release/install confirmation pass. Upgrade the installed
CLI, then retain its binary hash. CLI 0.1.45 does not contain the correction.
The source version stays **0.1.9**; do not remove its README declaration.

```bash
brew update
brew upgrade agentpm
agentpm --version  # Must report 0.1.46 or newer before continuing.
export BAND1_PUBLISH_CLI="$(command -v agentpm)"
shasum -a 256 "$BAND1_PUBLISH_CLI" | tee "$BAND1_SMOKE/publishing-cli.sha256"
# Publish the corrected Node dependency first.
cd "$BAND1_EXAMPLES/tools-node/github-issues"
pnpm build
pnpm test
"$BAND1_PUBLISH_CLI" lint --strict
"$BAND1_PUBLISH_CLI" publish --dry-run
"$BAND1_PUBLISH_CLI" --base-url https://api.agentpackagemanager.com publish \
  --namespace zack --sign --key-id "$BAND1_KEY_ID" \
  2>&1 | tee "$BAND1_SMOKE/publish-github-issues.log"

# Publish the Skill that selects that corrected Tool.
cd "$BAND1_EXAMPLES/skill-packages/issue-triage-playbook"
"$BAND1_PUBLISH_CLI" lint --strict
"$BAND1_PUBLISH_CLI" publish --dry-run
"$BAND1_PUBLISH_CLI" --base-url https://api.agentpackagemanager.com publish \
  --namespace zack --sign --key-id "$BAND1_KEY_ID" \
  2>&1 | tee "$BAND1_SMOKE/publish-issue-triage-playbook.log"

# Finally publish the Agent selecting the new Skill.
cd "$BAND1_EXAMPLES/agent-packages/devwork-python"
git diff -- agent.json README.md
"$BAND1_PUBLISH_CLI" lint --strict
"$BAND1_PUBLISH_CLI" publish --dry-run
python3 - <<'PYCODE'
import tarfile
with tarfile.open('target/agentpm/devwork-copilot-0.1.9.tar.gz') as archive:
    names = archive.getnames()
    print(names)
    assert names.count('agent.json') == names.count('README.md') == 1
PYCODE
"$BAND1_PUBLISH_CLI" --base-url https://api.agentpackagemanager.com publish \
  --namespace zack --sign --key-id "$BAND1_KEY_ID" \
  2>&1 | tee "$BAND1_SMOKE/publish-devwork-copilot.log"
```

Expected order: **`@zack/github-issues@0.1.2`**, then
**`@zack/issue-triage-playbook@0.1.1`**, then
**`@zack/devwork-copilot@0.1.9`**. These publish successfully through
`/v1/tools/publish/init` and `/finalize`, with a normal package URL. The Registry
validates the selected composition. The Agent publish itself does not republish
its dependencies: the preceding two commands deliberately publish their new
versions. Other dependencies, including summarize-text 0.1.10, remain unchanged.

The corrected archive has a different digest from the rejected upload. It
needs a fresh reservation; if init returns `409 publish in progress` while the
old reservation is still unexpired, wait for normal expiry before retrying. Do
not replace bytes in a reservation bound to the old digest or manually edit
production rows/storage.

If either publish fails, retain the error and stop that case. A later verify
failure does not undo a successful immutable publication.

## 5. Verify both new releases in clean consumers

```bash
mkdir "$BAND1_SMOKE/new-tool"
cd "$BAND1_SMOKE/new-tool"
agentpm --base-url https://api.agentpackagemanager.com install \
  @zack/summarize-text@0.1.11 --require-signature --require-attestation --machine \
  2>&1 | tee "$BAND1_SMOKE/new-tool-install.log"

mkdir "$BAND1_SMOKE/new-agent"
cd "$BAND1_SMOKE/new-agent"
agentpm --base-url https://api.agentpackagemanager.com install \
  @zack/devwork-copilot@0.1.9 --require-signature --require-attestation --machine \
  2>&1 | tee "$BAND1_SMOKE/new-agent-install.log"
python3 "$BAND1_EXAMPLES/scripts/release_examples.py" verify \
  devwork-copilot @zack/devwork-copilot@0.1.9 "$PWD" \
  2>&1 | tee "$BAND1_SMOKE/new-agent-composition.log"
python3 - <<'PYCODE' | tee "$BAND1_SMOKE/new-agent-dependencies.log"
import json
from pathlib import Path
packages = json.loads(Path('agent.lock').read_text())['packages'].values()
selected = {(p['name'], p['version']) for p in packages}
for expected in [('@zack/github-issues', '0.1.2'),
                 ('@zack/issue-triage-playbook', '0.1.1'),
                 ('@zack/summarize-text', '0.1.10')]:
    assert expected in selected, expected
    print('Verified exact dependency:', *expected)
PYCODE
```

Expected: both verified installs succeed. The existing example verifier confirms
the exact Agent version and declared Tool dependency, without SDK/model calls.
Keep the generated locks and all four publish URLs. Leave existing example-app
workspaces alone; updating them is not required for these clean-consumer checks.
