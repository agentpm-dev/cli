## Runtime boundary and rollout

The normative schema requires `standard: { "id": "agentpm", "version": "1.0.0" }`. Until the separate authoring rollout, the existing CLI path permits a missing declaration by removing only that required-field check from an in-memory copy of the bundled schema. It does not mutate the source schema or manifest and does not infer an APDS declaration or claim conformance. Present declarations always receive the pinned structural checks; an unknown/malformed declaration cannot fall back to a custom schema.

Default validation no longer consults a CWD-relative schema. Explicit local `lint --schema FILE` is development-only, carries a `schema.override` warning in human/JSON/NDJSON output, and fails under `--strict`. Declared manifests still satisfy the pinned schema. Arbitrary HTTP(S) overrides are rejected without fetching. Publish and package reject `--schema`, including file and HTTP(S) inputs, before preflight can imply contract validation under a replacement schema.

Saved-build publication also rechecks the descriptor's manifest against the bundled schema after its existing digest and typed checks. A regression test rewrites an archive and honestly recomputes every affected digest, then proves a blank description still fails preflight. Integrity alone cannot establish structural validity. Descriptor validation supplies no packaged-file context, so it does not accidentally inspect the publisher's working directory as if it were the extracted build.

Blank descriptions are now schema errors, with no duplicate CLI warning. Rust and Python read the identical explicit Unicode `White_Space` class and shared description cases. The schema tests distinguish ordinary whitespace, U+200B and U+001C rather than inheriting different language shorthand/trim behavior. Leading/trailing whitespace around nonblank text is not rewritten.

Prior tolerance tests were updated where this milestone intentionally defines the previously opaque field or removes automatic CWD lookup. The Knowledge writer still proves preservation of schema-valid fields absent from its typed reader, and two builds remain byte-stable. The earlier M1A.1 snapshot remains evidence of the already-released 0.1.36 behavior; the new candidate does not retroactively change that binary or old package bytes.
