## Implementation and scope decision

The Rust CLI now provides an independent APDS evaluator in `crates/agentpm-cli/src/manifest/apds.rs` with `apds/graph.rs` and `apds/content.rs`. It reads actual supplied manifests and context, never fixture expectations. It reuses the bundled canonical schema, existing Stage 1 kind/union diagnostics and existing local semantic helpers; `lint_output.rs` is unchanged.

No parser change was needed for optional Agent dependencies: the existing typed parser already accepts absent Tools, Profiles and Loop fields, and the dependency-free Agent passes the actual validator. The parent `manifest.rs` change only declares the new child module.

`commands/lint.rs` exposes the engine through explicit scopes:

```sh
agentpm lint --apds standalone path/to/agent.json
agentpm lint --apds packaged --package-root path/to/package path/to/package/agent.json
agentpm lint --apds resolved --graph selected-graph.json path/to/agent.json
```

M2B supplies the engine and explicit integration needed to exercise real CLI behavior. **M3B retains ownership of strict ordinary-authoring defaults and broad preflight integration.** Ordinary `lint`, publish, install, scaffolding and legacy behavior retain their existing paths. An ordinary lint pass remains narrower than a requested complete-package assessment. This boundary was explained to the user before implementation; no M3A/M3B/M4/M5/M6 checklist is completed here.

Explicit APDS evaluation rejects `--schema` and `--fix`, ignores CWD schema copies and uses the bundled standard offline. Unknown declarations return `unsupported` without applying a replacement contract. A missing/malformed declaration is evaluated by the strict pinned contract in these modes. JSON/NDJSON keep the existing report envelope and add APDS standard/level/status, evaluated/unevaluated rule lists, notes and `runner_evaluated: false`; findings use existing `LintIssue` rule/path fields. Pretty output uses the existing renderer plus a scope summary. Only a conformant requested scope exits successfully.

The graph input is local JSON with exact artifact descriptors and per-owner dependency edges. Relative manifest paths resolve against the graph file. Checks cover selected kind/name/version constraints, embedded-versus-supplied identity, missing/extra edges, phase names and Memory selectors, including Agents nested under Template compositions. Unreadable dependency documents leave dependent checks incomplete; an explicitly observed malformed JSON document is a definite defect. They do not select arbitrary installed names, resolve from a Registry or mandate an AgentPM lockfile.

Packaged checks use an explicit complete root and enforce content boundaries through symlinks. They cover Knowledge documents/counts/bytes and the existing supported float32/index representation, Skill resources, Template content roots, Tool literal file/directory selections, readme/license references, and Draft 2020-12 Memory schemas/local references/governance annotations. Actual record-schema references cannot fetch remote data; an explicit local-only resolver denies external resolution. Schema-tree traversal distinguishes schema keywords from ordinary example/default data and property names.

The public capability matrix and commands are in `scripts/README.md`, linked from the CLI README. The bundle's conformance quickstart now includes the optional actual-Rust integration command. `agentpm-api/docs/v0.1/cli/lint.mdx` documents explicit scopes and results without internal milestone language. The Registry repository has documentation-only changes.

## Reviewed corpus and probe corrections

The shared corpus still has **129 validation cases**, **28 separate Runner observations** and unchanged semantic rules/manifest schema. Two M2A verification gaps were discovered by actual execution:

1. The earlier acceptance probe checked only process success. Existing lint discovery silently skipped explicitly named files such as `tool.json`, printing “No agent.json found” with success. Consequently the previous **41-positive-manifest acceptance claim did not establish validation of every listed file**. Explicit APDS mode now accepts actual supplied filenames and fails when no manifest exists. The probe requires exactly one actual conformant APDS JSON report per file. A new Python regression rejects discovery-only, empty-array and legacy-only fake reports. The corrected probe now actually evaluates all 41 distinct positives.
2. `skill-inherited-only.json` removed the Agent's direct `echo` Tool dependency but accidentally retained its named MCP Tool binding. BIND-005 requires MCP-selected Tools to be directly declared, so the positive input contradicted its expected validity. The unrelated MCP binding was removed; global Skill inheritance, expected outcomes, rule definitions and the other MCP restriction scenarios are unchanged. This aligns the input with its original purpose rather than weakening the validator to hide a difference. The unpublished candidate's checksum inventory was regenerated. The user-confirmed M2B review sign-off covers this correction.

M2A's historical review status is retained, with this correction linked from its verification record. No published standard version was modified or retagged.

## Decisions, limits and remaining acceptance

- **D03:** One normative corpus, independently implemented Rust validation, real CLI integration and a focused test-only result projection. Graph context belongs to the CLI implementation input, not a new mandatory APDS protocol. No implementation-specific validator was placed in the standard directory.
- **D19:** Report requested evaluation level and actual certainty. Known violations take precedence over unavailable/unsupported checks; unknown standards are not interpreted using another contract. Runtime interpretation and readiness remain separate. Ordinary authoring rollout and Registry/lock/UI status integration remain in their owning milestones.
- **Capability limits:** Unknown vector/index representations and complex or ref-mediated non-persistability projection reasoning return `unsupported` with unevaluated rules. Direct source-schema requirements and annotation syntax are checked; the engine does not pretend a shallow scan proves arbitrary composed-schema satisfiability. No Runner-only rule is claimed from these validator results. These limits are explicit in the capability matrix and docs.
- **Review sign-off:** User confirmed Claude review passed with no findings on **2026-11-14**, including the implementation and recorded probe/fixture corrections.
- **Hosted CI sign-off:** User confirmed all CLI CI jobs passed on **2026-11-14**, satisfying the remaining M2B completion gate. This is user-confirmed hosted evidence; no workflow run ID or independently retrieved job log is asserted. **M2B is complete.** Registry Python parity, later rollout and production release remain separate.
- **Later work:** M2C implements independent Python validation/parity. M3B switches ordinary authoring/preflight defaults. M4 owns Registry publication enforcement, M5 install identity/closure, and M6 Runner preflight/interpretation. No task from those milestones is marked complete here.
