# Harness M20A / M20A.1 Manual Verification

Manual coverage for Milestone 20A and 20A.1: phase output preservation, provider required-tool behavior, fallback observability, bounded Section 4 cross-phase rendering, cross-phase action ledger measurement, Harness Control prompt orientation, authored outcome descriptions, and live-provider measurement.

These tests use a disposable `harness-m20a-test` directory. Deterministic capture tests do not require real provider keys. Live measurement tests do require OpenAI and Anthropic keys.

## Coverage Target

| Requirement | Manual coverage |
|---|---|
| Explicit-outcome phases force a provider-native action on OpenAI and Anthropic | Tests 1 and 2 inspect captured provider request bodies |
| `phase_complete` advertises output guidance | Tests 1 and 2 inspect captured provider schemas/descriptions |
| Missing `phase_completion.output` preserves same-turn assistant content through canonical output | Tests 1 and 2 fixture-validate `phase_output_fallback`; live Tests 4-6 showed this fallback is not currently reachable because providers emitted explicit `phase_completion.output` with no completing-turn assistant text |
| Section 4 cross-phase state has budget header and visible truncation markers | Test 3 |
| Section 1 includes Harness execution-model and phase-boundary orientation for native providers | Tests 1 and 2 inspect captured provider request bodies |
| Authored outcome descriptions render next to outcome IDs | Tests 1, 2, 8, and 9 |
| Section 4 explains compact handoff semantics even before ledger-specific wording | Test 3 inspects later captured provider bodies |
| Live providers no longer need missing-completion repair turns in the common objective-style scenario | Tests 4 and 5; live success came from required tool choice plus explicit `phase_completion.output`, not the fallback ladder |
| Live measurement records null outputs, completing-turn content/output, exact repeats, changed-argument rework, outcome distribution, repeats after success/failure where observable, and Section 4 budget markers | Tests 4, 5, 6, 8, 9, and 10 |
| `repeat_after_success` distinguishes repeats of completed prior actions from retry-after-failure | Test 11 self-tests the analyzer join |
| Authoring quality is measured as its own axis with tool availability held constant | Tests 12 and 13 repeat the objective scenario against a high-quality authoring fixture with the same phase tool bindings |
| Pre-change baseline can be compared with the same measurement unit | Test 7 |

## 1. Deterministic OpenAI Capture: Required Tool Choice And Output Fallback

This points the built-in OpenAI provider at a local capture server. The first provider response includes assistant text plus a `phase_complete` call with no `output`. Expected result: Harness emits `phase_output_fallback` with `applied:completing_turn`, and both `phase_result_ready` and final terminal output stay non-null.

This is a deterministic fallback-ladder test. In live provider runs, required tool choice may cause providers to put the answer directly in `phase_completion.output` with no assistant text beside the tool call. In that common live shape, precedence step 1 is the success path and this fallback does not fire.

```bash
mkdir -p "$M20A_RUNS/openai-fallback"
rm -f "$M20A_RUNS/openai-fallback/bodies.jsonl"
rm -rf "$M20A_WORK/.agentpm-state-m20a-openai"
PIDS="$(lsof -ti tcp:18120 || true)"
test -z "$PIDS" || kill $PIDS

"$AGENTPM_MANUAL_PYTHON" "$M20A_WORK/scripts/m20a_capture_server.py" \
  --provider openai \
  --scenario fallback \
  --port 18120 \
  --log "$M20A_RUNS/openai-fallback/bodies.jsonl" \
  >"$M20A_RUNS/openai-fallback/server.stdout.txt" \
  2>"$M20A_RUNS/openai-fallback/server.stderr.txt" &
SERVER_PID=$!
trap 'kill "$SERVER_PID" 2>/dev/null || true' EXIT
until curl -fsS http://127.0.0.1:18120/health >/dev/null; do sleep 0.1; done

export OPENAI_API_KEY="m20a-capture-key"
export OPENAI_BASE_URL="http://127.0.0.1:18120/v1"
REPORT="$M20A_RUNS/openai-fallback/report.json"
(cd "$M20A_WORK" && "$APM" harness \
  --config agentpm.m20a.openai.harness.json \
  --headless \
  --scope user=m20a-openai-fallback \
  --input "Find out whether the agentpm new command is ready, then finish with the answer." \
  --report "$REPORT" \
  >"$M20A_RUNS/openai-fallback/stdout.txt" \
  2>"$M20A_RUNS/openai-fallback/stderr.txt")

"$AGENTPM_MANUAL_PYTHON" "$M20A_WORK/scripts/m20a_assert_capture.py" \
  "$M20A_RUNS/openai-fallback/bodies.jsonl" \
  openai \
  fallback \
  | tee "$M20A_RUNS/openai-fallback/assertion.txt"

TRACE="$("$AGENTPM_MANUAL_PYTHON" - "$REPORT" <<'PY'
import json, sys
from pathlib import Path
report = json.loads(Path(sys.argv[1]).read_text())
print(report["trace_path"])
PY
)"
"$AGENTPM_MANUAL_PYTHON" "$M20A_WORK/scripts/m20a_analyze_trace.py" "$TRACE" \
  | tee "$M20A_RUNS/openai-fallback/summary.txt"
```

Expected:

- `assertion.txt` says OpenAI sent `tool_choice=required`.
- `summary.txt` includes `model_repair_requested: 0`.
- `summary.txt` includes `phase_result_null_outputs: 0`.
- `summary.txt` includes `phase_output_fallback: {"applied:completing_turn": 1}`.
- `summary.txt` includes `phase_completion_without_output: 1`.

## 6. Combine Live Measurement Summaries

If the analyzer changes after live runs have already been captured, regenerate summaries from the saved report trace paths before combining results. This does not call providers again.

```bash
"$AGENTPM_MANUAL_PYTHON" - "$M20A_RUNS" "$M20A_WORK/scripts/m20a_analyze_trace.py" "$M20A_BUDGET_WORK/scripts/m20a_analyze_trace.py" <<'PY'
import json
import subprocess
import sys
from pathlib import Path

runs = Path(sys.argv[1])
workspace_analyzer = Path(sys.argv[2])
budget_analyzer = Path(sys.argv[3])

for report in sorted(runs.glob("**/report*.json")):
    data = json.loads(report.read_text())
    trace = data.get("trace_path")
    if not trace or not Path(trace).exists():
        print(f"skip {report}: trace unavailable")
        continue
    analyzer = budget_analyzer if "openai-budget" in report.parts else workspace_analyzer
    summary = report.with_name(
        "summary.txt" if report.name == "report.json" else report.name.replace("report-", "summary-").replace(".json", ".txt")
    )
    summary.write_text(subprocess.check_output([sys.executable, str(analyzer), trace], text=True))
    print(f"regenerated {summary}")
PY
```

This produces a compact table from the six live summary files.

```bash
"$AGENTPM_MANUAL_PYTHON" - "$M20A_RUNS/live-openai" "$M20A_RUNS/live-anthropic" <<'PY'
import sys
from pathlib import Path

def read_summary(path):
    data = {}
    for line in path.read_text().splitlines():
        if ": " not in line:
            continue
        key, value = line.split(": ", 1)
        data[key] = value
    return data

print("provider sample repairs null_outputs completion_with_output completion_without_output assistant_on_completion exact_cross same_action_cross changed_arg_cross same_action_within changed_arg_within section4_markers")
for provider, root in [("openai", Path(sys.argv[1])), ("anthropic", Path(sys.argv[2]))]:
    for path in sorted(root.glob("summary-*.txt")):
        sample = path.stem.split("-")[-1]
        data = read_summary(path)
        print(
            provider,
            sample,
            data.get("model_repair_requested", "0"),
            data.get("phase_result_null_outputs", "0"),
            data.get("phase_completion_with_output", "0"),
            data.get("phase_completion_without_output", "0"),
            data.get("completing_turns_with_assistant_content", "0"),
            data.get("cross_phase_exact_repeats", "0"),
            data.get("cross_phase_same_action_rework", "0"),
            data.get("cross_phase_changed_argument_rework", "0"),
            data.get("within_phase_same_action_rework", "0"),
            data.get("within_phase_changed_argument_rework", "0"),
            data.get("section4_budget_marker_prompts", "0") + "/" + data.get("section4_output_stub_markers", "0"),
        )
PY
```

Use this table to decide:

- if `model_repair_requested` is consistently zero, required tool choice is doing its job;
- if `phase_result_null_outputs` is zero, 20A output preservation is working in live runs;
- if `phase_completion_without_output` remains common but output still survives through fallback, the fallback is earning its keep;
- if `completing_turns_with_assistant_content` is zero, live providers are not exercising the fallback ladder; output preservation is coming from explicit `phase_completion.output`;
- if any exact-repeat, same-action, or changed-argument rework counters remain non-zero, that is 20A.1 evidence, not a 20A failure;
- if Section 4 markers never appear in ordinary runs, budget defaults are likely generous for common cases.

## 14. Combine High-Quality Authoring Summaries

```bash
"$AGENTPM_MANUAL_PYTHON" - \

import sys
from pathlib import Path

def read_summary(path):
    data = {}
    for line in path.read_text().splitlines():
        if ": " not in line:
            continue
        key, value = line.split(": ", 1)
        data[key] = value
    return data

roots = [
    ("openai", "low-quality-with-tool", Path(sys.argv[1])),
    ("anthropic", "low-quality-with-tool", Path(sys.argv[2])),
    ("openai", "high-quality-with-tool", Path(sys.argv[3])),
    ("anthropic", "high-quality-with-tool", Path(sys.argv[4])),
]
print("provider scenario sample exact_cross same_action_cross changed_arg_cross repeat_after_success repeat_after_failure outputs outcomes")
for provider, scenario, root in roots:
    for path in sorted(root.glob("summary-*.txt")):
        sample = path.stem.split("-")[-1]
        data = read_summary(path)
        print(
            provider,
            scenario,
            sample,
            data.get("cross_phase_exact_repeats", "0"),
            data.get("cross_phase_same_action_rework", "0"),
            data.get("cross_phase_changed_argument_rework", "0"),
            data.get("cross_phase_repeats_after_success", "0"),
            data.get("cross_phase_repeats_after_failure", "0"),
            data.get("phase_result_outputs", "0"),
            data.get("outcome_distribution", "{}"),
        )
PY
```
