# APDS 1.0.0 semantic cases

These cases illustrate the [semantic rules](../semantics.md). They describe the context an evaluator needs and the expected interpretation. They do not prescribe a fixture serialization, diagnostic format or Runner implementation. A deterministic validation check examines declarations and supplied relationships; a Runner check observes capability or execution behavior.

The [fixture index](fixture-index.json) maps these case letters to concrete validation inputs and expected results. [Runner observations](runner-observations.json) supply the separate state/action/observation scenarios, including Q–T. See the [quickstart](README.md#run-the-corpus-checks) for commands and scope boundaries.

Cases about capability exposure, trigger dispatch or interpretation cannot be verified merely by accepting or rejecting a manifest. Validators can check available references and declared relationships without running models, Tools, approvals or Memory operations.
